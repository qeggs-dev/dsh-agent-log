## RawCall 项目新建（2026-11-27，从「软件层面的…

RawCall 项目新建（2026-11-27，从「软件层面的 Flipper Zero」逐步收敛而来）。

### 定位

在运行时手动调用任意动态库的导出函数，参数一律按 64 位整数/指针传递，核心不做类型解释——即「把操作系统暴露的标准接口统一到一个内存工作台上」。落点 〈工作区〉/rawcall（独立 git 仓库，初始提交 20620a8，44 个文件）。

### 四层

core/（C 写的 rawcall.dll，唯一 ABI 真源）、gui/（Rust + egui 0.29 桌面应用，默认前端）、sdk/{python,java,javascript}/（薄绑定，共用 docs/CONTRACT.md 的 13 个概念命名）、docs/CONTRACT.md（跨语言契约）。

### 全部已实测

C 冒烟读到 68620898304 字节真实内存、只依赖 KERNEL32+msvcrt；GUI --selftest OK 且窗口渲染已截图确认；Python 39 项 unittest 全绿；Java 用 JDK21 FFM preview 端到端通过；

JS koffi 3.3.8 + node:test 12 项全绿。

### 核心约束

只支持整数/指针参数（最多 12 个），不支持浮点/结构体 by value/可变参数；不做安全护栏（用户 2026-11-27 明确「用这个软件的人默认他知道自己在干什么」，因此不做权限分级、不做确认框），但健壮性仍要做（参数校验与崩溃隔离不是安全策略）；Windows x64 优先，32 位不支持。

两种工作模式（用户同日定）：直接运行（对当前进程操作）与子进程运行（隔离；因为地址空间隔离，父进程只能传结构化描述，不能传裸指针）。
