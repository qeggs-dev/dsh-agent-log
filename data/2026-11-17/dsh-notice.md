## 通知卡片插件 notice（2026-11-17，`D

\Projects\Deepseek_Harness_Workspace\dsh_plugins\notice`，包名 `@local/dsh-notice`，已安装并 git 提交）：Host 注册 `notice` 工具（必填 description + notice，可选 title、color），通知存内存并通过 `/dsh-notice/state|action|events` 暴露；Client 用 `shell.overlay` 把卡片放在**主会话窗口内容区**左上角（只认 `[data-slot="main.conversation"]` 内的 `[data-conversation-content]`，避开右侧子代理标签页的同类节点；rect 定位并每秒重测）。卡片写明发起会话的标题与 ID；点击 = `uiWorkspace.openSession` 跳转并注入 `opened`，左划 = `dismissed`，右键多行回复 = `replied`（Enter 发送 / Shift+Enter 换行 / Esc 取消）。三种动作都以 `cordis-host-runner` 来源注入发起会话：open/dismiss 用 `agent.inject`（不唤醒），reply 用 `followup`（冷会话走 `sessionController.prompt`）。表面/边框/阴影/文字用 `--dsw-specific-menu`、`--dsw-alias-border-l2`、`--dsw-elevation-panel`、`--dsw-alias-label-*`；INFO/SUCCESS/WARN/ERROR 预设色亮暗两套（亮色 55% 状态色混白、暗色用状态 token 原样），HEX 原样。已实测：三张卡片的 open/dismiss/reply 注入、点击跳转到顶层会话、`change_style` 真实深浅切换；子智能体会话的点击跳转未成功（`openSession` 对非工作区行会话静默失败）。`dist/` 有插件 tgz 与含 SKILL.md 的 skill zip。 另有可选 `timeout` 参数（秒，0/省略=不超时，上限 604800）：到点仍未被处理时卡片自动从所有页面移除，并向发起会话注入 `action="timeout"` 的上下文（含 timeout_seconds，说明用户可能没看到）；用户先点击/左划/回复则清除定时器，不会既记录动作又记录超时。实测 timeout 5 与 8 均在到点后自动消失并收到 timeout 事件；先被点击的卡片只收到 opened、无 timeout。 带 timeout 的卡片底部有一条居中、占满卡片内宽的进度条（accent 色）+ 右侧「N 秒」倒计时，按 Host 下发的 expiresAt 每 250ms 重算；实测 20 秒卡在 18 秒时 89%、6 秒时 29%，到点卡片消失并收到 timeout。 动效：浮层裁切在主会话内容区（overflow:hidden，左边界即侧栏边缘），新卡片从左侧（侧栏后）translateX(-120%)→0 滑入 240ms；处理/超时消失时卡片 translateX(-120%) 向左滑出 200ms，同时外层 slot 用 grid-template-rows 1fr→0fr 收拢 220ms，下面卡片随之上移；prefers-reduced-motion 关闭动画。实测入场 t0 -427px/opacity 0 → t350 0/1；出场 90ms 时 -373px、slot 行高 3.5px；中间卡片消失后下方卡片 392→260。 卡片支持自定义按钮（actions，≤4，primary/danger/default）与多选题（questions，≤4 题、每题 ≤8 选项）：选项单选，全部选完才启用「提交答案」；点击按钮或提交答案会移除卡片、唤醒会话并注入 `button`（含 button_id/label）或 `answered`（含每题 prompt+选项 label）。Host 通过 `ctx.provide('notice', …)` 开放服务：`create(options)` 同步返回 `{id, result}`，result 在 button/answered/opened/dismissed/reply/timeout/cancelled 时解析一次；`list()` 返回未处理通知，`dismiss(id)` 取消并解析为 cancelled。临时探针插件实测：ctx.notice.create → 点击「API Yes」→ result 返回 `{noticeId, action:'button', buttonId:'api-yes', label:'API Yes'}`，同一点击也向该会话注入了 button 事件；探针已卸载并移入回收站。 新增三个配套工具：`lst_notice`（列出调用者所在会话树——lead + 全部子代理——的未处理通知，共享一份列表，子代理与 lead 双向可见；带 id/title/正文/颜色/发起会话/剩余超时/按钮/问题）、`del_notice`（按 id 从共享列表移除，不记录动作、不唤醒会话，服务等待方收到 cancelled）、`operation_notice`（open/dismiss/action；每次调用先 `ctx.approval.request`，只有 allowed-once 才执行，否则通知不变）。三者都限制在调用者的会话树内。`open` 会下发 `openRequest`（seq+ts）让页面在 10 秒内跳转到发起会话。实测：子代理先看到 lead 的 notice-1，创建 notice-2 后双方列表都有两条；del_notice 删除 notice-2 生效；operation_notice 在 never 策略下返回『Not approved (rejected)』且 notice-1 保持不变。
