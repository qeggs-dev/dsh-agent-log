## `tencent-connect/dsh-qqbot`

是腾讯 QQ 官方出的 DSH 接入插件（MIT、TypeScript、npm `@tencent-connect/dsh-qqbot`，2026-08-14 建库，查时 v0.5.5 / 569 star / 46 open issues）。形态是**纯 Cordis 插件**（`export const inject = ['agents']`，配 `dsh.bundle.patch: ./cordis.patch.yml` 与 `dsh.client` web 半包），不是独立服务：LLM/会话/工具全由宿主提供，插件只做 IM 协议驱动。**接入走 QQ 官方 Bot API v2**（`@tencent-connect/qqbot-nodejs`，`transport: 'websocket'`，baseUrl `https://api.bot.qq.com`），因此需要开放平台的 AppID/AppSecret；扫码绑定用 `@tencent-connect/qqbot-connector` 的 `startQrConnect`，手机 QQ 扫完直接返回 appId/appSecret，写入 profile 的 `cordis.patch.yml` 触发 HMR 自动重载（`apply()` 刻意不 await 扫码，否则阻塞 Host ready）。**关键约束**：被动回复必须带入站消息的 `msg_id`（群 5 分钟 / 私聊 30 分钟窗口、同一 msgId 最多 4 条，`reply-limiter.ts` 限 4），超限后按「显式 msgId → 缓存里的其他 msgid/event_id → 主动推送」三级兜底；流式只对 c2c 被动回复生效，群聊始终整段发。**结构**：`sessionKey = qqbot:<appId>:<scope>:<peerId>`（私聊 peer=user openid、群 peer=group openid），映射存 `model-prefs.json`，解析顺序「进程内复用 → resume → create」，且 resume 失败只有确认盘上确无该会话才允许新建（否则同一 id 写进多个 project 目录会让宿主整个会话列表打不开）；入站经 SDK 中间件洋葱（配对码认领 → accessPolicy → historyBuffer → mentionGate → sanitizer → rateLimiter → slashCommand → questionAnswer → concurrencyGuard(merge) → quoteRef → attachmentProcessor）后，5 层拼成 body 再 `agent.followup()`。**出站靠 TurnTracker 判回合归属**（全局监听 `session/event`，桌面续聊/定时任务这类「非 QQ 输入」的回合按 `proactiveDelivery` 走主动推送）。**它与我的 `repeater-backend` WS 桥方向（`id:20261023-026/027`）不冲突但生态位不同**：那条路走 NapCat/个人号协议、无需开放平台资质但受风控；这条走官方机器人 API、稳定但需注册机器人与申请主动消息配额。直连 `github.com` 的 HTML 打不开（TLS 不通），但 `api.github.com` 用 Node fetch 正常可读。
