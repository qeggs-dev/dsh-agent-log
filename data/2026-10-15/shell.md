## 用户三个想法的合流，现在有一句可对外的说法

**「带身份和注册表的 shell 作业控制」**（他自己从选项中确认了这一句）。含义：**任务（TID）是一等公民**、集中注册运行时；元操作是「tool 作为外壳拉起另一个 tool / 前台执行 / 后台执行 / 管道执行 / 重新等待」这类元操作——即 **Unix shell 的作业控制语义 + 任务身份与注册表**（shell 只有 PID，而 PID 不携带「这是什么、谁改过它、现在是什么版本」，这就是他的增量）。**相对 DSH 他自陈两条差别**：①**命令可组合可调度**（这是主张，对手是「agent 应完全自主、不该被调度器管」那一派）；②**语言是 Python 而非 TS**（这是定位而非主张，把他放进更大的 agent 生态池）。他最初把它说成「自修改 Agent 框架 + Unix 单元组合 + 十分干净的微内核」，其中**「微内核」实为最小原语集，不是内核**

## 上述框架的**核心已由他在两个同系列（同一系列、不同组件）的项目…

上述框架的**核心已由他在两个同系列（同一系列、不同组件）的项目里独立重复实现过两次**：**不是重写，是两次内嵌**，重复的原因是他「希望两个系统都能用到这套可操作性」而当时**缺一个可挂载的形态**。两份核心思想相同，**其中较新的一份更小、复杂功能更少**；他自陈差异是「**一部分有意削掉、一部分还没做到**」——因此**两份都要保留、都要读**（旧的那份带着新那份「还没做到」的部分）。目前该系列**只有这两个组件**需要这套核心，但以后可能增加
