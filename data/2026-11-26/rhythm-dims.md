## 维度音游 rhythm-dims 新建（2026-11-26）

用户先提「1~4 维的音游」，随后逐步收敛为「判定空间逐级降维」——N 维空间里运动的音符穿过 (N−1) 维判定切片，在切片上留下交点；切片的旋转与位移都由谱面控制。落点 `〈工作区〉/rhythm-dims/`（独立 git 仓库，分支 main，初始提交 243c131）。

### 形态

纯静态 ESM、零框架、无构建、零运行时依赖（`npm run serve` 起 4174）；测试 `node --test --test-isolation=none "tests/*.test.js"`（普通 `node --test` 在沙箱会因 spawn EPERM 失败），26 项全绿。

### 四个模式

1D→0D「点」戳泡泡（单键，0D 判定点沿一条 1D 线摆动，泡泡从两侧滑向它）、2D→1D「线」1K 音游（1D 判定线随谱面摆动，音符沿法线落下）、3D→2D「面」（2D 判定面由谱面倾斜/升降，音符沿法线落到面上，鼠标点落点）、4D→3D「体」（超立方体在四维旋转，屏幕上是 w=0 的三维切片线框；

四维球截面半径 √(R²−w²)，音符从无到有长大，最大即判定时刻）。判定窗口 PERFECT ±45ms / GREAT ±85ms / GOOD ±130ms / MISS 160ms；

音乐用 OfflineAudioContext 合成 32 拍 Am–F–C–G loop（零素材），AudioContext 时钟即游戏时钟。

### 验证

`scripts/verify.mjs` 用 headless Edge + CDP 逐模式截图并读运行时状态，必须在完全权限下跑（沙箱禁止监听回环端口、Edge 也起不来），实测四模式 running、时钟前进、判定循环产出 miss、零异常；截图在 `screenshots/`（gitignore）。

### 实现改为

3D 谱面给音符分配 line(0-2)+offset，模式在判定面上铺 3 条漂移/倾斜的判定线，音符沿法线落下，鼠标点落点；4D 谱面分配 face(0-2)+自由落点，模式在 3D 判定体中叠 3 张判定面（彩色环+十字+中心点，漂移/倾斜），音符从上方落到面上，点投影落点。

原「超立方体切片 + 四维球截面」方案弃用（geometry/hypercube 与单测保留，未再渲染）。修了 projectPoint 传入数组导致 NaN 进 createRadialGradient 的 4D 崩溃。

【同日再修正（最终语义）】用户再调整 3D/4D 的判定：3D→2D 是「3D 数据透视投影到 2D，音符落到某条判定线上，点击那条线即可」（不要求点落点）；4D→3D 是「4D 先投到 3D 再投到 2D，点击射线必须命中 3D 空间中的判定面，交点靠近落点才算击中」。

### 实现

3D 用 createCamera 透视 + 3 条 z 向排布的 3D 判定线（投影成屏幕线段，判定=点击点到线段距离 ≤ 34px，三线颜色对应音符）；

4D 用 project4Dto3D（w 轴缩放，w 从 5 到 0）+ projectPoint 双重投影，判定=unprojectToPlaneAt 求点击射线与面交点，须在圆盘半径内且与落点 xz 距离 ≤ 0.8 世界单位。30 项单测全绿，headless 四模式+旅程零异常。提交 03245ce。

【同日再改：砍 4D，专注 1D~3D】用户决定不做 4D。判定 = 维度数减一：1D = 0D 判定点（音符从线两端靠近原点，点击原点判定）；2D = 1D 判定线（音符靠近底边、重合时点击）；3D = 2D 判定面（音符靠近底面、重合时点击）。

每个音符绑定一个判定单元（点/线/面），判定只看绑定单元，∩ 交集不需要单独实现（用户原话「通过让所有音符都绑定一条线的方式来变相解决」）。

### 升维动画

1→2 时线端点消失、延伸成判定线；2→3 时地面画出 3D 网格、相机从正对 smoothstep 插值到自由透视（Game.entryProgress，0.8s）。

判定线/面有水平（底边/地面）与竖直（竖线/竖面）两种朝向，由 journey 段落配置：pulse 16 → lane h 32 → plane h 32 → lane v 32 → plane v 32 → lane h 32 → pulse 16（192 拍）。

4D 的 volume 模式与 chart 已删除（geometry/hypercube 与单测保留）。30 项单测全绿，headless 三模式+旅程零异常。提交 f954c0f。

【同日修：3D 音符缩放】用户指出 3D 环境音符没有正确缩放。原因是半径用「落点缩放比 + 上限 1.4」近似，等于把透视压扁，且音符从法线方向靠近（俯视相机下高处离相机更近、更大，方向反直觉）。

### 改为

音符位置 = 落点 + 上方 drop + 深度 depth（从远处+上方接近判定面），半径 = 固定世界半径 0.42 × projectPoint 返回的 scale，得到真实近大远小。提交 cc1264d。

### 已验证成立的概念

①判定维度 = 世界维度 − 1：1D→0D 判定点（音符从线两端靠近原点、点击原点）、2D→1D 判定线（靠近底边/竖线、重合时点击）、3D→2D 判定面（靠近地面/竖面、重合时点击）；②每个音符绑定一个判定单元（点/线/面），判定只看绑定单元，∩ 交集不需要单独实现；③升维动画：1→2 线端点消失、延伸成判定线；

2→3 地面画出 3D 网格、相机从正对 smoothstep 插值到自由透视（entryProgress 0.8s）；

④维度旅程按 4 小节切段（pulse 16 → lane h 32 → plane h 32 → lane v 32 → plane v 32 → lane h 32 → pulse 16 = 192 拍），分数跨段延续；

⑤3D 音符透视缩放 = 固定世界半径 0.42 × projectPoint 的 scale，音符从远处+上方接近判定面（近大远小）。被否决/弃用的方向：4D 整体砍掉（超立方体切片、4D→3D→2D 双重投影、多判定面都试过）；3D 的多判定线/多判定面/点线判定/射线-面求交均被后续方案取代。
