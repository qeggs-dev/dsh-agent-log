## 新增项目 **dlcore** 于 `〈工作区〉/dlcore/…

新增项目 **dlcore** 于 `〈工作区〉/dlcore/`（Go 1.27.3，零外部依赖，约 2100 行）：多来源分片下载内核。

用户 2026-11-02 拍板「**专用设计，尽可能不被 API 影响高性能结构**」——不兼容 ADv1、不含 aria2 层，`internal/core` 里没有任何外部协议概念（无 gid / bitfield / status 枚举）。

### 四条主线

①单所有者调度（只有 run() 改状态，其余 goroutine 只做「领片→下载→写盘→上报」，调度逻辑无锁）；②片用 `WriteAt` 直写最终文件（无临时片、无拼接步骤）；③片数远多于并发数（并发是信令量，权重只决定每条通道占几个 worker，不决定下一片给谁）；

④事件分两类（生命周期事件不可丢 / 状态帧可丢且为绝对值，`Attach()` 给冷启动快照）。

### 已实现

GET+Range 探测（不用 HEAD）、`Content-Range` 逐片校验、长度不一致的镜像摘除、`(片,通道)` 重试黑名单、熔断三态（连续 3 次或窗口失败率 ≥50% → 冷却 4s 起翻倍至 5min → 半开探测）、尾部二分、暂停保留已写字节、跨引擎重启续传（状态文件只存「已落盘区间」，片由区间与总长重算）、SHA256 收尾校验、不支持 Range 时退化单流。

### 验证

10 项测试含 `-race` 全过（多源并行 / 运行中断流切换 / 404 探测期摘除 / 长度不符 / 暂停续传 / 重启续传 / 校验失败 / 无 Range）；本地 3~4 通道 16 MiB 端到端字节与哈希一致。

### 开发中修掉两个真 bug

①`handlePrepare` 无条件设 active，会把「探测阶段按的暂停」吞掉；②状态文件原是调度循环内同步写，本机过滤驱动下实测让一条 `Pause` 命令延迟 **180ms**，已改为快照 + 独立 writer goroutine、退出时同步刷最后一份。

**产物位置**按 20261101-003：构建到 `〈工作目录〉/dlcore/out/`、可执行副本在 `〈工作目录〉/dlcore/run/`。

### 已知限制

无分块级抽样一致性（多源内容不同但长度相同时只能靠整份 SHA256 发现）、速度是 EWMA 而非精确积分、全局并发只有一个旋钮、CLI 只有 `get` / `serve`。
